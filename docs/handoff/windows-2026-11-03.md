# 윈도우 세션 작업 요청 (맥 → 윈도우, 2026-11-03)

이 문서는 맥 세션이 윈도우 세션에 남기는 작업 지시서다. 아래 순서대로 진행하고, 결과는 마지막 "보고" 형식으로 `docs/handoff/windows-2026-11-03-result.md` 에 적어 같은 브랜치에 커밋·푸시한다.

## 0. 규칙
- `main` 에 직접 푸시하지 않는다. 세션 브랜치나 `integration/2026-11-03` 에만 푸시한다(리모트 이름이 `wiki` 면 아래 `origin` 을 `wiki` 로 읽는다).
- 캡처 이미지(`screen.png` 등)는 공개 레포에 올리지 않는다. 텍스트로 정리한 사실만 올린다.
- 출처 없는 금융 정의를 쓰지 않는다. 일반 정의는 맥이 공개 출처로 채운다. 윈도우는 화면에서 확인한 사실(단위·형식·빈 값 표시·탭·조건)을 기록한다.

## 1. 브랜치 받기
```
git fetch origin
git switch integration/2026-11-03      # 로컬에 없으면: git switch -c integration/2026-11-03 origin/integration/2026-11-03
git log --oneline -1                   # 21d7e735 이상이어야 한다(scripts/regenerate_all.py 존재)
```

## 2. 생성물 재생성과 검증 (한 번에)
```
uv run python scripts/regenerate_all.py --site
```
- `../check-e2e` 가 있으면 E2E 가져오기를 포함한다. 위치가 다르면 `--e2e-dir <경로>`.
- 끝의 "기대값 점검"이 모두 통과해야 한다: researched 필드 ≥ 68, `None` 링크 없음.
- 확인할 수치: validate `ok: true` 와 미해결 관계 ID 0, 검색 평가 recall@1 ≥ 0.864, pytest 전체 통과, Quartz 빌드 성공.
- 실패하면 실패한 단계 이름과 출력 끝부분을 결과 문서에 적는다. 임계치를 낮춰 통과시키지 않는다.

## 3. 통과하면 커밋
- 생성물(`knowledge/`, `content/`, `ontology/`)을 `integration/2026-11-03` 에 커밋하고 푸시한다.
- 그 뒤 `main` 병합·배포는 사용자 확인 후에 한다.

## 4. 화면 값 기록
`docs/field-capture-requests.md` 의 15개 화면에서, 각 화면의 표시명에 대해 아래를 텍스트로 기록한다.
- 값 예시와 단위, 소수점, 부호, 색
- 값이 비었을 때의 표시
- 나타나는 탭·조건
- 기간·종류를 바꿨을 때 값 변화
특히 뜻이 갈리는 항목(스프레드, 3M, CD, 기준가, 민평, 만기일)은 어떤 의미로 쓰였는지 화면 값에서 판단해 적는다. 1300(주식현재가)은 `screen.png` 위치를 확인하고, `clock_overlay_detected` 경고 화면은 재촬영이 필요한지 적는다.
기록은 기존 E2E 관찰 파일의 필드 정의 구조(`field_definitions`)에 맞춰도 되고, 어려우면 결과 문서에 표로 적어도 된다.
