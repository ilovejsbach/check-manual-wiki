# kcm 위키 작업 분리: lib-ops(데이터)와 stock-market(게시)

작성: 2026-10-20. 근거: 작가 지시 — 지금까지 만든 위키를 게시 테스트해야 하므로 이제부터 작업을 lib-ops와 stock-market으로 나눠서 한다. (결정 D-054, 요구서 `2026-10-20-kcm-wiki-publish-request.md`)

## 1. 누가 무엇을 하나
| 구분 | lib-ops (`kcm-book-to-wiki` 워크트리, 볼트 `vault-finance`) | stock-market (Quartz 5) |
|---|---|---|
| 책임 | 위키·보완층·2부 후보의 **내용 정확성**, 형식 검사, 보완 조사·판정, 델타 생성, 데이터 쪽 결함 수정 | **게시 파이프라인**: Quartz 설정, `content/` 동기화, 빌드, 게시 테스트, 별도 레포(계정 `ilovejsbach`), 외부 게시, 내부 반입용 델타 zip |
| 쓰는 곳 | 볼트 `wiki-korean-capital-markets/`, lib-ops 저장소 | stock-market 저장소(`content/`는 동기화 생성물) |
| 하지 않는 것 | Quartz 설정·빌드·배포, git 원격·push, GitHub 레포 | 위키 내용 수정(데이터 루트를 고치지 않는다), 보완 조사, 정본·OCR 텍스트 게시 |
| 게시 테스트 | 하지 않는다(이미 한 로컬 점검은 폐기했다) | **한다.** 먼저 로컬 시험 빌드, 푸시·배포 전에 작가 확인 |

## 2. 둘 사이의 통로 (우편함)
- 공용 우편함은 `/Users/koscom/workspace/stock-market/handover/` 한 곳이다. 서로의 저장소를 직접 고치지 않는다.
- **lib-ops → stock-market:** 요구서(한 번), **델타**(추가 작업마다 갱신 알림: 커밋 해시, 바뀐 게시 대상 파일 목록, 건수). 델타는 `loop.py delta --book kcm`으로 만들고 `docs/requests/deltas/`에 기록한다.
- **stock-market → lib-ops:** 게시 테스트 결과와 데이터 쪽 문제는 `handover/feedback-YYYY-MM-DD-<주제>.md`로 적는다. lib-ops 세션이 읽고 데이터를 고친 뒤 델타로 알린다.
- 작가가 중간에서 세션을 연결한다(세션이 서로를 대신 시작하지 않는다).

## 3. 게시 테스트 절차 (stock-market 몫)와 피드백 형식
순서: ① Node 22 이상 확보(전역 설정을 바꾸지 말고 임시 방식) ② 새 작업 폴더나 브랜치에서 `content/`를 요구서 2절 규칙으로 동기화(손복사 금지) ③ 한국어·분석 도구 끔 등 최소 설정 ④ 로컬 빌드 ⑤ 점검 ⑥ 피드백 작성. **push·레포 생성·배포는 작가 확인 뒤에만.**
점검 항목과 피드백 형식 — 각 항목은 "결과, 근거(파일/예시), 누구 몫(데이터/설정)"을 적는다:
1. 빌드 성공 여부와 오류·경고, 빌드 시간
2. 생성 페이지 수 대 `content/` 문서 수(373 + 보완 문서)
3. 깨진 위키링크 수와 예
4. 별칭(`aliases`)·같은 이름 충돌 처리
5. `[src: kcm pN]` 출처 토큰의 화면 표시(글자 그대로인지; "원본 p.N" 각주형으로 바꿀지)
6. frontmatter(`status: draft`, `type`)가 의미 없이 노출되거나 Quartz의 `draft` 처리로 페이지가 빠지지 않는지
7. 한국어 검색·그래프·목차 동작
8. 외부 리소스 요청 수(CDN, 구글 폰트): 내부 반입을 위해 **0건**이어야 한다
9. 결과물에 내부 경로 문자열(`/Users/`, `lib-ops`, `vault-finance`)이 없는지
10. 가장 큰 페이지(보완 `timeline.md` 약 650KB)가 렌더·검색 색인에 부담이 되는지 — 부담이면 분할 요청(데이터 몫)
11. 저작권 고지·출처 표시 문구 반영 위치

## 4. 흐름
요구서(1회) → stock-market 게시 테스트 → 피드백 → lib-ops 데이터 수정 → 델타 → stock-market 재빌드 … 테스트 통과 후 작가 확인 → 외부 게시 + 내부 반입 zip. 이후 보완 작업(아카이브 재확인 등)은 델타로 지속 반영한다.
