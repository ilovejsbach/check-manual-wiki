핵심: 데이터 루트 /Users/koscom/workspace/vault-finance/wiki-korean-capital-markets/ 는 읽기 전용이다(그쪽 파일을 고치지 않는다). 게시 대상은 wiki/ 의 index·chapters·concepts·institutions·regulations·metrics·books 와 supplements/ 의 timeline·by-chapter·by-page·README·part2/ 이다. 게시 금지는 wiki/_meta/, wiki/CLAUDE.md, work/, books/ 이며 supplements/ 의 author-check·corrections·candidates·held·*.jsonl·config·coverage·stats 도 제외한다. 게시는 두 갈래다(방법론은 ai-newsletter-automation 의 CLAUDE.md publish 절과 docs/delivery 를 읽기 전용으로 참고): ① 외부 공개 GitHub(정적 사이트, Pages) ② 내부망 반입용 델타 zip(변경분만, 목차 포함; 내부망은 압축 해제와 git 뿐이고 내부 GitLab 게시는 사람이 직접 하므로 너는 zip 생성까지만). ai-weekly 와 다른 점은 사이트 생성 도구가 Quartz 라는 것 하나이고 나머지 방법론은 같다. 내부망 PC 에는 node 도 없으므로 zip 에는 Quartz 가 빌드한 정적 결과물을 담는다. 공개 게시이므로 저작권 고지와 출처를 사이트 전체에 표시하고 문서는 전부 초안 표시를 단다. 시행 예정·입법예고는 확정처럼 바꾸지 않는다.
주의: 이 저장소의 git origin 이 Quartz 원본(jackyzha0/quartz)이다 — 거기로 push 하지 않는다. 게시 저장소는 ai-weekly 사이트와 같은 GitHub 계정(ilovejsbach)의 별도 새 레포이며 기존 ai-newsletter-site 에 섞지 않는다. 새 레포를 만들고 원격을 바꾸는 일은 작가 확인을 받고 한다. 레포 이름과 Pages 주소는 네 재량이다. 인증 정보는 파일·로그에 남기지 않는다. 빌드는 먼저 로컬에서 확인하고, push 는 작가 확인 뒤에 한다. 사이트 이름·주소·구역 위치는 요구 사항이 아니라 네 재량이다. 외부 수집(크롤링)은 하지 않는다(데이터는 이미 준비됨).
데이터는 앞으로도 갱신된다. 갱신되면 lib-ops 쪽이 커밋 해시와 바뀐 파일 목록을 알려 준다 — 그때 content/ 를 다시 만들고 재빌드한다. content/ 는 동기화 스크립트(제외 규칙 포함)로 만든 생성물로 두고 손으로 고치지 않는다.
