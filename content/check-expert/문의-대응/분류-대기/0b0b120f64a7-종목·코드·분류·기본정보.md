# 공식 문서 연결 대기 — 종목·코드·분류·기본정보

> 기존 위키 화면·기능에 자동 연결되지 않은 비식별 신호입니다. 삭제하거나 임의 연결하지 않고 사람 검수 대기 상태로 보존합니다.

- 관련 신호: 22건
- 상태: `candidate` / `unmapped`
- 후보 유형: faq 21건, procedure 16건, caution 4건, troubleshooting 2건

## 대표 사례

### 후보 1

- 고객 질문·증상: CHECK API의 옵션 기본정보(복수종목) 조회 시, 기본정보와 달리 복수종목 요청에서 "Error while <값> Query" 오류가 반환되어 추가 라이센스가 필요한지 문의했습니다.
- 당시 대응 기록: 사이트에서는 종목을 쉼표 없이 각각 입력해 실행하면 조회되고, 프로그램에서는 배열 형태로 요청해야 합니다. 페이지 하단 샘플처럼 주식종목코드 자리에 옵션종목코드를 넣으면 조회되며, 현재 조회에 문제가 없으므로 사용 중인 프로그램이 배열 구조로 요청하는지 확인하도록 안내했습니다.
- 검토 과제: 연결할 기존 문서 또는 신규 문서 필요 여부 결정

### 후보 2

- 고객 질문·증상: check api에서 basic_info_all은 1초 간격 연속 호출이 되는데, 복수 종목을 넣는 basic_info_all_port는 1초~3초 간격이면 두 번째부터 실패하고 10초 간격이어야 성공한다고 했습니다. 문서의 초당 1회 제한이 종목 수만큼 내부 카운트되는지, 정확한 호출 제한이 무엇인지 문의했습니다.
- 당시 대응 기록: 해당 API를 내부에서 테스트한 뒤 전화로 안내했다고 답했습니다. 문제가 계속되면 안내한 메일주소로 코드를 보내 주면 지원하겠다고 했으며, 제한 기준의 구체적 수치는 기록되지 않았습니다.
- 검토 과제: 연결할 기존 문서 또는 신규 문서 필요 여부 결정

### 후보 3

- 당시 대응 기록: 종목정보 인자를 "1*015"에서 "*091"로 바꿔 보도록 안내했습니다. 시장코드는 8003 화면에서 확인할 수 있습니다.
- 검토 과제: 연결할 기존 문서 또는 신규 문서 필요 여부 결정

### 후보 10

- 고객 질문·증상: 해외 주식의 ISIN코드를 기준으로 CHECK 티커 코드를 얻는 방법이 있는지 문의했습니다. 지수 데이터의 티커와 CHECK 티커가 미세하게 다른 경우가 있다고 합니다.
- 당시 대응 기록: 현재는 CLIST 함수로 ISIN코드와 단축코드를 함께 불러와 매칭하는 방법뿐입니다. 예시는 =CLIST("","",-1,"*194","<값>","","<값>,<값>","DESC","<값>=true;") 입니다. CLIST의 최대 호출 개수가 6천개이므로 거래소 기준 등 추가 필터가 필요하며, 거래소 조건에 NSQ, AMX, NYS를 각각 넣어 나스닥, 아멕스, NYSE 종목 목록을 얻을 수 있습니다.
- 검토 과제: 연결할 기존 문서 또는 신규 문서 필요 여부 결정

- 당시 대응 기록: =CLIST("","",-1,"*001,*003","<값>","","<값>,<값>","DSC","<값>=true;") 함수를 사용하면 됩니다. -1은 전체 데이터 조회, *001,*003은 유가 및 코스닥 시장 대상이며, 조회 항목으로 표준코드와 단축코드를 지정합니다.
